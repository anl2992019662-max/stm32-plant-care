# 手机与电脑控制

## 电脑

Python 3.10+，包含Tk。源码提供 GUI，不要求付费串口软件。

```powershell
# 软件演示：先用C编译器运行测试，生成本机模拟适配器
python tools/test.py --cc '"C:\Tools\zig\zig.exe" cc'
python desktop/app.py --demo

# 实物连接
python -m pip install -r requirements.txt
python desktop/app.py
```

实际 Zig 路径由你解压位置决定；可从[官网](https://ziglang.org/download/)获取。演示和测试需要本机编译器；Keil 的 Arm 编译器用于固件，不能运行电脑的本机测试。Linux可使用gcc，并安装系统Tk包。

演示程序编译的正是 `firmware/src/plant.c` / `codecs.c`，通过 `tests/simulator.c` 注入虚拟传感值和时间，不调用真实ADC、GPIO或Flash。初始标定完成且预热完成，方便立即演示；它无法验证电路、驱动和真实植物效果。

1. 启动演示后点“启动演示”，默认手动。选“自动养护”，再切换预设场景。
2. “高温干燥”会请求风扇、短时水泵和补光；泵冷却/累计预算仍有效，所以不是每次点击都会浇水。
3. 实物先在Windows设置中配对HC-05，确定对应的出站SPP COM端口；在工具里选择该端口连接。也可用3.3V USB-UART接PA9/PA10调试，必须断开HC-05的TX，避免两个发射端对接同一RX。
4. 查看实际遥测后选择“蓝牙控制”，再点击各设备请求。只有本工具主动进入蓝牙控制后才周期发PING；软件失去遥测超过6秒会尝试STOP，STM32自身仍有10秒租约。
5. 参数命令可在底部输入，格式见[协议](protocol.md)。界面显示原始ADC、故障解释及实际输出位。数据超过6秒会提示超时；卡片保留的是最后一帧，不是新测量。
6. “记录CSV”选择保存文件；再次点击停止。CSV含UTC接收时间与 `software_demo` 标识，演示数据不能用作硬件测量证据。请自行决定是否公开采集日志。

关闭或断开本工具时，如果它持有蓝牙控制，会尽力发送STOP；物理断链仍依赖固件超时。选自动模式后断开电脑，自动控制可以继续运行；首次实物测试必须有人看护。

## 手机

面向支持经典蓝牙 SPP 的 Android 手机。选择能收发ASCII、发送LF/CRLF且能周期发送指令的蓝牙串口工具；不需要项目专用App。iOS兼容性不在本次交付范围内。

1. 在系统蓝牙中配对所购HC-05，配对凭据以具体模块说明为准，不在仓库硬编码。
2. 在串口工具连接该模块，启用接收文本和每条指令后的换行。
3. 发送GET确认JSON。先使用风扇等空载指示检查，泵的测试最后做。
4. 发送MODE REMOTE，配置每秒发送PING；再发送SET指令。停止周期心跳后，确认10秒后输出归零。
5. 发送STOP结束。一次只用一个SPP客户端；电脑和手机不应同时争用同一模块。

HC-05是近距离蓝牙，不是Wi-Fi/互联网。配对成功也不证明串口UART波特率正确；乱码先检查模块数据模式9600/8N1、共地和3.3V信号。手机工具不会替你标定真实传感器。
